# Workspace refactoring assessment, 2026-10-26

Branch: `refactor/simplify-workspace`.

This pass audited all ten crates and consolidated repeated implementations while retaining the
crate graph and existing public interfaces. The measured reduction is **224 code lines (0.18%)**.
The requested significant size reduction was **not achieved**: the audit did not establish a safe
large deletion that preserves the required behavior, compatibility and performance. No claim is
made that this is a mathematically minimal codebase or that tests prove every possible behavior.

## Audit and simplifications

All crate manifests, first-party source/test inventories, support scripts, fixtures and CI were
examined for duplication, dead code and dependency use. Editor, storage/config/workspace and
services audits have file coverage ledgers. UI review used workspace-wide pattern/structure scans
and direct review of the relevant implementations, callers and tests; it is not a claim that every
UI source/test line received a separate manual review. No unused direct dependency was established.

The implemented changes are:

- **Form and picker models:** Field constructors own text/toggle/choice defaults. Item constructors
  own empty hints, absent badges and ordinary action dispatch. Existing keys, labels, initial values,
  choices and action payloads remain at their call sites.
- **Path choosers:** Eight simple chooser continuations share their detached-task/error/lifetime
  handling. Their dialog options, selected-path order, first-path behavior and focus updates stay
  with their commands. Stateful comparison pickers and background package installation stay separate.
- **Coordinates:** Five legacy Document entry points delegate to the existing typed Coords
  implementation. Public entry points remain; CRLF clipping, EOF/extreme clamping and raw-line APIs
  retain their behavior.
- **Indentation:** Document indentation, explicit-width indent/unindent and indentation conversion
  share a formatter. The explicit-width commands share their line worker while retaining the
  distinct empty-line and default hard-tab behavior, selection mapping and undo paths.
- **Formatting and automation:** Statistics and search progress reuse the existing decimal-grouping
  function. Running and final command-output drains share stdout-first, short-circuiting combined
  limits and the same error text; cancellation, timeout and process cleanup remain intact.
- **Appearance:** One private registry emits all 53 unchanged public Ui constants and the accepted
  role inventory. Equal default colors still have independent override keys. A temporary comparison
  against the original parser checked every role with valid/invalid colors and malformed inputs.
- **Spelling:** Three private native implementations now live directly in their existing Checker
  trait methods. Existing public inherent methods, native bodies, owner checks and cancellation
  sequence are preserved.
- **Test support:** The two harnesses include one ordered editing-source fixture list and one
  polling helper. Four highlighting checks share cumulative byte-position lookup while retaining
  their assertions. No existing test, assertion, ignored flag or performance budget was removed or
  weakened. Two coordinate/indentation characterization tests were added and passed before and
  after the associated refactoring. An intentional indentation-guard mutation made the new test
  fail; restoring the exact source made it pass again.
- **Cargo metadata:** Removed four redundant library target declarations and made terminal inherit
  its existing dependency versions from the workspace. All ten packages' targets, dependencies,
  features, editions and versions match the baseline metadata. No crate boundary or dependency
  direction changed; source fixture sharing remains test-only.

A fresh independent review reconstructed the task-only patch against the captured baseline and
found no actionable correctness, readability, architecture, security or performance regressions.
It separately checked callbacks, coordinate/indentation edges, output limits, native bodies,
appearance keys and test preservation. It was a static review, not independent runtime proof.

## Areas retained after review

- Atomic and in-place writes, hard-link/symlink behavior, ACL/xattr preservation, pinned-directory
  checks, file history, recovery and write leases enforce distinct failure/race guarantees.
- Shared-document/view separation, ordered edits, selection/undo mapping, IME handling and
  asynchronous generation/cancellation checks protect different state transitions.
- Syntax caches, parser families, Unicode coordinate/display layers, bounded work and worker
  priority are covered by different correctness/performance contracts.
- Git clean filters, partial staging, index locks and rename-aware history have distinct policies;
  terminal bounded I/O and descendant cleanup preserve process and output ordering.
- Public compatibility reexports and wrappers remain even when local callers use another path.
  Crate mergers and deleting features, languages or tests were not justified by the audit.
- Sharing the small deterministic test generators was left out: a new support layer would add
  indirection for a small test-only reduction, with seed/draw-order risk and no production benefit.

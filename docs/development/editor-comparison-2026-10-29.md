## Agent execution rules

1. Preserve the feature selection already supplied by the user. When assigned this whole file with no selection, execute **Recommended** entries only. Execute **Optional** or **Deferred** entries only when their IDs are selected. Skip unselected entries and continue without asking to expand scope.
2. Read applicable repository instructions and [verification instructions](verification.md), inspect the current worktree, and recheck each selected feature at the current commit. The baseline describes the audit, not a requirement to reset Git. If a feature already meets its acceptance criteria, verify it and record completion instead of rebuilding it.
3. Execute selected entries one at a time. Listed dependencies are included prerequisites; complete them first. If both N26 and N27 are selected, implement N27 before N26. Otherwise entries are independent unless current implementation proves a shared prerequisite.
4. Each entry's Requirement, Specification and Acceptance define its scope. Concrete defaults below are the Orlo target behavior; peer editors are references, not exact clone specifications. Follow existing module/UI patterns and reuse current parsers, snippets, protected writes, Git subprocesses, PTYs and settings.
5. Complete a vertical slice: model/backend, real user command, applicable UI/settings, meaningful regression checks and user documentation. A helper or unreachable backend alone does not complete an entry. Keep new options off by default unless the entry explicitly defines another default.
6. For asynchronous edits/results, capture identity/version/selection, validate the whole result before applying, and reject stale work. User text transforms must support undo, Unicode/graphemes, writable-state checks and shared views. File/process operations use existing cancellation/error handling and preserve user data on failure.
7. Keep Orlo a text editor + Git + terminal. Use dependencies only when needed for a selected feature and record the reason. Keep changes limited to selected requirements and compatible migrations; preserve existing behavior outside the selected feature.
8. Check a feature only after its acceptance criteria and applicable verification pass. Record the verified revision (or HEAD plus uncommitted state), commands/results and any manual checks or genuine limitations in a completion note below that entry. Distinguish tests run from tests merely inspected; never mark a blocked or partly implemented group complete.
9. Continue through all selected entries. If one needs an unavailable external prerequisite, record that specific block and continue independent selected work. Do not treat Optional/Deferred sections as an instruction to implement them automatically.

The first 15 entries are the default Recommended set. Original F/E/L/G/T and N IDs remain stable. U01–U07 identify previously uncatalogued utility/UI details.

## Excluded from execution

These are reference directions from the comparison, not implementation tasks:

- Debuggers/DAP, breakpoints, watches, remote/device debugging and runtime inspection.
- Advanced refactoring/project-analysis platforms beyond current rename/code actions and the specified lightweight navigation.
- AI chat, agents, generated commit messages and assistant-session orchestration.
- Live evaluation/notebooks, browser-connected programming and Acme-style command/9P environments.
- Browser live preview, specialized HTML/CSS authoring, publishing and deployment.
- Collaboration servers, participant cursors, chat, ACLs and hosted PR/account/review clients.
- Leo-style outline databases, clones and literate-document models.
- SQL/database, cloud/container, remote-workspace and execution platforms. F05 is limited to an explicitly selected single-file transport.
- General-purpose plugin/expression runtimes, executable modelines, marketplaces and automatic tool installation.
- Rich image/media/ebook/archive readers, canvases, clipboard organizers and workspace dashboards.
- Terminal daemons, remote multiplexers and process resurrection.
- Ports to other operating systems.

Additional LSP variants (multiple servers, inlay hints, code lens, pull diagnostics, server-initiated workspace edits/resource operations), project-wide heuristic completion indexes, full structural workspace querying and platform-specific floating/secondary-selection interfaces have no implementation requirement in this file. Their evidence/uncertainties remain in the research reference. Existing ordinary completion, accessibility/IME or OS Services must not be classified as absent merely because a peer describes a different implementation.

```text
Completed: <feature ID>, <verified commit or HEAD + uncommitted state>
```
